# L1 离线只读缓存

> 优先级: P3（不紧急）
> 状态: 已规划
> 日期: 2026-05-18

## 想法

类似 Git，项目数据本地保存一份，断网也能查看。经分析，完整双向同步成本过高，仅实现 L1 只读缓存。

## L1：离线只读缓存

### 目标

- 断网/服务器宕机时，仍可浏览项目列表、Issue 列表
- 联网时静默更新缓存
- 离线时顶部显示提示："离线模式（数据可能过期）"

### 实现范围

| 端 | 方案 | 说明 |
|----|------|------|
| 前端 | IndexedDB 缓存 | 缓存 list_projects / list_issues 结果，离线读缓存，联网更新 |
| MCP | 本地 SQLite 缓存 | check_connection 失败时降级缓存模式，只读走缓存，写操作报错提示 |

### 不做

- L2 离线操作队列（离线写 → 联网重放）
- L3 全量双向同步 + 冲突合并
- 凭据缓存（安全风险）

### 分析记录

- 完整离线同步的难点：结构化数据冲突难合并（vs Git 文本 diff）、工作流/通知的一致性、安全风险
- L1 覆盖 80% 场景（断网能查看），L2/L3 边际收益低
