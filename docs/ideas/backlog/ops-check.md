# 运维场景 + Computer-use Agent

> 日期: 2026-05-18

## 1. 运维项目 — 服务器定时检查

**优先级: P2（中期）**

### 已具备

| 能力 | 说明 |
|------|------|
| Server 模型 | IP、凭据（加密）、健康检查 |
| `check_server` 端点 | TCP 连通性测试 |
| 工作流 `schedule` 触发 | 支持 cron 定时 |
| MCP `list_servers` | Agent 可查询服务器列表 |

### 待补充

| 缺失 | 说明 |
|------|------|
| `ServerCheckLog` 模型 | 记录检查历史（时间、结果、响应时长） |
| 告警机制 | 检查失败 → 工作流触发通知 |
| Agent 自主修复 | 可通过"调用外部 Agent"步骤实现（见下方） |

### 实现思路

本质是工作流的应用场景：

```
工作流（cron 每小时触发）
  → Step 1: check_server（TCP 连通性）
  → Step 2: 条件判断（失败？）
  → Step 3: 通知人类 / 调用修复 Agent
```

后端只需新增 `ServerCheckLog` 模型，其余用现有工作流即可编排。

---

## 2. Computer-use Agent — E2E 最终兜底

**优先级: P3（不紧急）**

### 结论：不应内置，作为外部服务

PM 系统的职责是**管理和协调**，不是**执行具体操作**。Computer-use Agent 应该是独立服务：

```
PM 系统 ──(工作流/MCP)──► Computer-use Agent 服务 ──► 浏览器
                              ↑
                        独立部署，独立维护
```

### PM 系统只需

1. 工作流中支持**"调用外部 Agent"步骤类型**（webhook/http 调用）
2. MCP 提供触发接口

### 风险

- 浏览器操作不稳定、慢、难以断言结果
- 适合作为最终兜底，不应作为主要手段
- 实现依赖 LLM 视觉理解，成本高
